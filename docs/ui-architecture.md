# UI architecture

Sona's interface is Go all the way down: [MyGo](https://github.com/egoist/mygo)'s native UI (`github.com/egoist/mygo/ui`; GTK3 on Linux, AppKit on macOS, Win32 on Windows) drawing on the GPU from the same process that holds the services, the library and the playback coordinator. There is no web view, no IPC and no generated bindings: a view calls a typed service and reads the DTO it returns. This page is the map of `internal/ui`; `docs/architecture.md` has the process model and the platform seams, `docs/design.md` the visual direction and `internal/services/doc.go` the service contracts.

## Layout

```
cmd/sona ─► internal/ui/app ─► internal/ui/features/<name> ─► internal/ui/{module,kit,store,theme,i18n,media,account}
                                                   │                └─► internal/services (typed services, DTOs)
internal/ui/app ─► internal/ui/module (types only)
```

| Package | Holds |
|---|---|
| `internal/ui/app` | The windows (the main window, the mini player's, the tray) and the macOS menu bar, the sidebar and top bar, the status banner, the router, the shortcut dispatcher; builds the Env and the module list (`modules.go`: one line per feature, whose order routes, event handlers, shortcuts and slots follow; nav items sort by their own `Order`; a duplicate module ID panics at start-up) |
| `internal/ui/module` | The contract between the shell and a feature: `Env`, `Module`, `Route`, `NavItem`, `Shortcut`, `Slots`. Types only: no windows, no state |
| `internal/ui/features/<name>` | One package per feature (album, library, player…). Features never import each other |
| `internal/ui/account` | The sign-in and account views the account dialog (`features/auth`) and the first-run setup (`features/onboarding`) share: the sign-in reducer, the credentials, code, browser and token forms, the signed-in view, the keyring notices. A shared UI package like `kit`, so two features need not import each other |
| `internal/ui/kit` | Components shared by features (Button, Artwork…), built on MyGo widgets and the theme |
| `internal/ui/media` | What MyGo lacks of the system's media stack: the player of motion artwork (MyGo's `ui/video` on macOS and Windows, `motion_native.go`: AVFoundation, Media Foundation; GStreamer through cgo on Linux, `motion_gst.go`; none without cgo, `motion_none.go`), `OpenMotion` (the motion cache's file into a looping, muted `ui.VideoPlayer`: Ready at once on Linux, when its first picture came with the system's), and the music video's pictures (`Feed`, which hands the CDM child's I420 frames to a bitmap; `Picture.YUV` is the image `Bitmap.UpdateYUV` shows) |
| `internal/ui/lyricsync` | The timing logic of synced lyrics (the sung line, rests, verses, word progress, per-song offsets), shared by Now Playing, full-screen lyrics and the mini player |
| `internal/ui/store` | The event bus, cached queries and the playback mirror: everything that comes from Go and changes |
| `internal/ui/theme` | Design tokens (colours light and dark, type, radii, space, motion), their application to MyGo's theme, Lucide icons, the interface font |
| `internal/ui/i18n` | `T`, `TC`, `ErrorText`, the locale and its formatters, over `locales/en.po` |

A feature reaches another feature's state only through `store` (the playback mirror, the queries) or a hook in `module.Env`. A new feature is a Go service (`internal/services/<feature>.go`, `<feature>_dto.go` and one `registry.go` line) and a package under `internal/ui/features` with one `modules.go` line.

## The module contract

A feature is a `module.Factory`, `func(env *module.Env) module.Module`, and keeps its state in its own struct; its views are methods on it.

```go
func New(env *module.Env) module.Module {
    l := &library{env: env}
    return module.Module{
        ID:     "library",
        Routes: []module.Route{{Pattern: "/library/albums", Title: func(*ui.Route) string { return i18n.T("Albums") }, Build: l.albums}},
        Nav:    []module.NavItem{{Section: module.NavLibrary, Label: func() string { return i18n.T("Albums") }, Icon: "disc-3", To: "/library/albums", Order: 1}},
        Init:   l.init,
    }
}
```

`Env` is built once by `app.New` (and by `uitest.New` in tests) and its fields never change. `Queue` and `ItemStates` are nil in an Env built by hand without services, and `Motion`, `Nav`, `HasRoute` and `Shortcuts` are nil without a shell. Its fields:

- **Services and state.** `Core` (typed service lookup: `services.Service[services.LibraryService](env.Core)` returns the `*LibraryService`), `Bus` (Go's events; `store.On` subscribes), `Queries` (the cached queries; `Invalidate(prefixes...)`), `Play` (`store.Playback`, the playback mirror), `Post` (runs a func on the main thread and redraws: how a goroutine hands its outcome to a view), `Log`, `Version`, `Dev` (a `-tags dev` build).
- **Items.** `Art` (the artwork loader), `Actions` (the item action registry), `Players` (`kit.ItemPlayers`, the shared item-play registry: discover registers how songs, albums, playlists and videos play, radio stations; the shared item components play through it) with `ItemsCtx(menus)` (the context those components take: router, route check, browser, players, the account's explicit restriction, artwork, motion and what plays), `ItemStates` (`kit.ItemStates`: the one library state and rating layer that every item menu, header and rating button reads and changes through; it follows `library:item-state` itself) and `Queue` (`kit.QueueCommands`: every feature that plays a collection or adds to the queue goes through it, so replacing a long queue of the user's asks first or offers Undo).
- **Shell.** `Nav` (the main window's router), `HasRoute` (`func(path string) bool`: whether a registered module's route pattern matches the path, `/album/{id}` matching `/album/42`; a feature renders a link only when it is true, so nothing links to a page that is not registered; call it while building a view, as the routes of modules built later are not known in a factory), `Shortcuts()` (every shortcut with the keys it answers to now), `Motion` (the `kit.MotionPolicy` the motion covers and tiles take), `Surfaces` (`store.Surfaces`: the open state of the account dialog and the first-run setup; any "Sign in" action calls `Surfaces.OpenAccount()`, Settings' "Set up Sona again" `Surfaces.OpenSetup(step)`; while the setup is open `OpenAccount` moves it to its Apple Music step instead), `Video` (the `store.VideoView`: whether the music video view is open, `Open`, `Close`, `Toggle`, `IsOpen`, the window's full screen it toggles, and the source of its pictures; any feature that starts a video calls `Video.Open`, the video feature draws the view), `OpenURL` (the system browser) and `Copy` (the clipboard).
- **Between features.** `PlayerControls` and `PlayerNotice` (`module.Point`s, below), `ConcertsShelf` (Home's concerts shelf) and `ArtistConcerts` (`func(c *ui.Context, artistID string, first bool)`: the artist page's "Upcoming concerts"), the last two set by the concerts module in its factory and building nothing while it is not registered.

What a module declares:

- **Routes** use MyGo's router patterns (`/album/{id}`, `/settings/{section...}`). The route memory, titles and the back and forward buttons are the shell's.
- **Nav** entries sit in the primary, library or footer section and sort by `Order`; `To` is one of the module's own patterns. Each gets a go-to shortcut (`Keys`, else Ctrl+1…9 or Alt+1…9 by position).
- **Shortcuts** have a stable `ID` (`<module>.<action>`): the settings store a user's bindings by it, so an ID is never renamed. `Keys` use v0.2.0's spelling (`Space`, `Ctrl+K`, `Shift+ArrowRight`). One key handler in the shell dispatches them: page-scoped ones skip text fields, the first match whose scope and `When` allow runs. `Unavailable` says why a key does nothing (the key is taken); `NoPalette` keeps a shortcut out of the command palette.
- **Slots** are places in the shell a module builds into: `Aside` (right of the page), `Overlay` (covers the page column; its optional `Close` is called when the page changes while it is open: back, forward, a swipe or a link show the new page, not a page hidden behind it), `Bottom` (the player bar), `Layer` (over the whole window; while `LayerOpen` the shell builds it as a modal overlay, so the window behind takes no input and assistive technology reads the layer alone, and the page is still built and drawn, so first paint is reported as always), `SidebarFooter`, `SidebarSection`, `TopBarSearch`, `TopBarAccount` (the top bar's trailing end: the account menu). A func builds nothing when it has nothing to show. A route or nav item exists only when its module is registered: there are no placeholders.
- **Init** runs once after the shell connects, on the main thread: subscriptions (`store.On`) and first snapshots.
- **Points** are places inside another feature's view, as Slots are places in the shell. A `module.Point` (zero value ready) is filled while the factories run, `Add(order, build)`, and built by its owner with `Build(c)`, in order. `Env.PlayerControls` is the player bar's right group, before mute and the volume (private listening is order 10; the sleep timer, lyrics and queue buttons add theirs), `Env.PlayerNotice` the line under the title while a song waits for the Widevine CDM. An `Env` is shared by pointer, so what a module adds is seen by the feature that builds the point, and no shell code is involved.

**Actions** (`[]kit.ActionDef`) are the module's item actions, single (`Target` a kind) and bulk (`Target: kit.KindSelection`); the shell registers every module's into one `kit.ActionRegistry` (`Env.Actions`), which `kit.ActionMenus` lists and shortcuts and the palette share by ID. A duplicate ID panics at start-up.

## Store, queries and events

All callbacks a UI author passes run on the main thread; everything in `store` is safe from any goroutine unless noted. Results and events come back through a `store.Poster`, which `app` supplies (`Window.Update` on every window: it runs the func on the main thread and redraws) and tests supply synchronously.

**Events.** `store.Bus` implements `services.Emitter`: the services emit into it from any goroutine. Events emitted before `SetPoster` are queued and delivered in order; afterwards each is posted in emission order. Subscribe with a typed handler, `store.On(env.Bus, services.EventPlaybackState, func(s services.PlaybackState) {…})`; a payload of another type is logged once and dropped.

**Queries.** `store.Use(env.Queries, key, fetch, opts…)` returns the cached `Result[T]` (`Data`, `Err`, `HasData`, `Loading`, `Fetching`) and starts a fetch on a goroutine when there is no data or the data is stale as a view starts using it. Call it from the view every frame: a view that goes unbuilt for a second and is built again is a new mount (TanStack's observer mounting), and only then is stale data refetched, with the old data showing meanwhile.

```go
lib := services.Service[services.LibraryService](l.env.Core)
r := store.Use(l.env.Queries, store.Key{"library", "albums", l.sort},
    func(ctx context.Context) (services.AlbumPage, error) { return lib.Albums(ctx, l.sort, false, "", 0, 1000) },
    store.Options{Stale: store.Forever})
```

- **Keys** mirror v0.2.0's TanStack keys (`["library","albums",…]`) and hold every input of the fetch. `Invalidate(prefixes…)` marks the queries below each prefix stale (all, with none), refetches the ones used in the last minute at once and cancels a fetch in flight; the rest refetch when next used. A module's `Init` ports v0.2.0's `eventHandlers` line for line: `store.On(…)` then `env.Queries.Invalidate(store.Key{"library"})`.
- **Options.** `Stale` (0: stale at once; `store.Forever` is v0.2.0's `staleTime: Infinity`) and `Keep` (an unused query is dropped after this, 0 is five minutes; dropping cancels the fetch's context). Fetches of one key never run twice at once; a failed query with no data is asked again only after 5 s, so a broken service is not asked every frame (`NoRetry` is TanStack's `retry: false`: the error stays until `Invalidate` or a new mount, for network reads whose failure is an answer); a panicking fetch becomes the query's error.
- `Set` writes data (optimistic updates, event payloads) and cancels a fetch in flight, whose answer predates the write; `SetIfEmpty` writes a snapshot only while nothing is there (check and write under one lock); `Peek` reads without fetching; `Reset` drops everything (sign-out).

**Playback mirror.** `store.Playback` follows `EventPlaybackState` and `EventPlaybackQueue`: `State()`, `Queue()`, and `Position()`, extrapolated from the last snapshot while playing (`PositionMs + now − At`, never before the snapshot, clamped to the duration when known; v0.2.0's `livePosition`). `Seed` sets it from the services' snapshots before the first event; `Patch` changes it locally while a command is in flight, until Go's next snapshot.

## Strings and locales

Every string the user reads (text, labels, tooltips, toasts, menu and command labels) goes through `internal/ui/i18n` and lands in the English catalogue `internal/ui/i18n/locales/en.po`.

```go
i18n.T("Add music by {name} to collect it here.", "name", artist)
i18n.TC("verb", "Play")                                        // with a msgctxt
i18n.T("{0, plural, one {# album} other {# albums}}", 0, n)    // Lingui's positional names: "0" or 0
```

- **The msgid rule.** The message and the context MUST be string literals at the call site: the English text is the msgid, the catalogue's identity of the message and the source of Apple's mapping. `go run ./cmd/i18ntool extract` reads `internal/ui` with `go/ast` and collects every `i18n.T("…")` and `i18n.TC("…", "…")`; a non-literal argument is an error. `extract` writes `en.po` and `en-XA.po` whole, one entry per message the code asks for (sorted, with the Go files as references; a message no call asks for is dropped); `extract -check` (part of `check`) fails when either is stale or a mapped message has gone. The msgids and contexts of v0.2.0 carry over byte for byte, positional placeholders included (`{0}`, `{1}`: the Go call names them `"0"`, `"1"`).
- **Messages** are ICU MessageFormat, parsed and formatted by MyGo (`i18n.ParseMessage`): named and positional arguments, `plural` and `select` with CLDR's rules, `#`, number and date formats. A message that does not parse panics under test and in dev builds, and an Apple or community translation that does not parse is left out (logged once).
- **Lookup order** for the locale shown: Apple's translation (`services.AppleTranslations`, set with `i18n.SetApple`, keyed by `applestrings.MessageID(msg, ctx)`), then the community catalogue (`i18n.LoadCommunity`, a `.po` keyed by the English msgids), then English, the call site's own text. `en-XA` is MyGo's pseudo-locale (accented, stretched).
- **Choosing the locale** is `ChooseTranslation` over `TranslationCandidates` (the account's storefront language, then the system's, up to the first English one) and `SelectableShare` (0.9), ported from v0.2.0's `locale.ts` with its tests; the language the user picked in Settings shows whatever its share. `LanguageOptions` builds the Language setting's list. `SetLocale`, `SetApple`, `SetRegional` (the system's and the account's tags, so an English UI on an en-GB system keeps 24-hour clocks) redraw through `i18n.SetPoster`.
- **Formatting:** `FormatNumber`, `FormatDate(t, DateMedium)`, `FormatClock`, `FormatDuration` (`m:ss`), `RelativeTime(t, now)` (v0.2.0's `relativeTime`: never, just now, N min./hr. ago, yesterday, N days ago; for freshness lines such as "Synced …" and "Updated 12 min. ago" of a fetched page), `RelativeDay(t, now, loc)` (when something was, in calendar days read in `loc`: today's minutes and hours, yesterday, "on Tuesday" for two to six days, "last week" to 13 days, "earlier this month", "in March" this year, "last year", then "in 2023"; for dates of the user's things, such as a playlist's "Updated …"), `CalendarDays` and `NextMidnight` (the arithmetic under it, which History's day headings share), `FormatDateTime` (the full date and time, the exact time behind a `RelativeDay` label), `List`/`ListOr` (a hand-keyed table of CLDR's list words), `Fold` (lower case without accents, what a filter folds both sides to), `Collator()` (`golang.org/x/text/collate`), all in the shown locale.
- **Formatting:** `FormatNumber`, `FormatDate(t, DateMedium)`, `FormatClock`, `FormatDuration` (`m:ss`), `FormatRunningTime` ("1 hr, 12 min") and `FormatTimeLeft` ("18 days, 6 hours") (v0.2.0's `Intl.DurationFormat` short and long; MyGo has no CLDR unit names, so `durations.go` keeps a table of CLDR 48.2.0's words (the version MyGo's tables come from) for 14 languages, with en-001, en-CA, fr-CA, Traditional and Hong Kong Chinese rows, English for any other), `ShortReleaseDate(t, now)` ("19 Nov", the year only when not this year's), `List`/`ListOr` (a hand-keyed table of CLDR's list words), `Collator()` (`golang.org/x/text/collate`), all in the shown locale; the date, clock and duration formatters follow the regional format locale (`Locales()[0]`), never the catalogue's language.
- **Errors.** Go sends codes, never text: `i18n.ErrorText(code)` words a `services.ErrorCode` with v0.2.0's msgids (an unknown or empty code gets "Something went wrong."), `i18n.ErrorMessage(err)` an error, preferring Apple's own wording of a sign-in failure Sona has no code for. A test checks that every `Code*` constant of `internal/services/errors.go` has its own text in `en.po`.
- **Apple's translations.** `apple-keys.json` maps Sona's msgids to Apple Music's string keys; `apple-keys-rejected.json` records the rejected pairs. Both sit in `internal/ui/i18n/locales/` with `en.po`, which Go embeds (package `locales`: `internal/i18n/applestrings` imports it). `i18ntool match` proposes mappings, `match -apply` moves reviewed ones in, `import` converts Apple's bundles for review (gitignored). Sona fetches Apple's text at run time; nothing of it is committed. CONTRIBUTING.md, "Strings and translations", has the workflow.
- Go's own catalogue (`internal/i18n/l10n`, notifications and file dialogs) is separate and unchanged: `extract` keeps both.

## Theme tokens

`internal/ui/theme/tokens.json` (embedded; dev builds read the file, which `theme.Reload` applies on the next frame) is the one source of colours, type, radii, space, metrics and motion. Colour names are v0.2.0's custom properties of `shared/styles/index.css` without `--`, light and dark (`ground`, `surface`, `raised`, `hover`, `active`, `line`, `control-line`, `ink`, `ink-muted`, `ink-faint`, `amber`, `amber-ink`, `on-amber`, `danger`, `positive`, `avatar-N-bg/fg`), the shadcn roles (`primary`, `ring`…), the role names (`play`, `play-ink`, `on-play`) and derived ones (`edge`, `selection`, `scrollbar`). A value is `#rrggbb[aa]`, another token's name, or `name/N` (that token at N% opacity).

- `theme.C("ink")`, `theme.Current().Type["title"]`, `.Radius["md"]`, `.Metric["sidebar"]`, `.Motion["feedback"]`: pages never hard-code a colour or a size. An unknown colour panics in tests and dev builds and is magenta in production.
- `theme.Apply(c)` at the top of every view sets the `ui.Theme` MyGo's widgets draw from, in Sona's colours and font, following the mode (`SetMode`: `ModeSystem`, `ModeLight`, `ModeDark`; `Dark()` reports what frames draw) and the desktop's text scale and high contrast (`Theme.WithPreferences` with those two only: MyGo's stronger borders, muted text, opaque focus ring and bolder scroll bars, and the larger font; the desktop's accent is left out, amber is Sona's); the scroll bar thumb's hover colour is the `scrollbar-hover` token; it builds a new theme only when something changed.
- `theme.Scope(overrides, children)` builds children with some colour tokens replaced (`C` looks in the innermost scope that names a token first): the way a page printed in its cover's colours redeclares `ink`, `hover`, `amber`… for what is inside (v0.2.0 set custom properties on the sleeve). Only colours read while children builds follow it, not ones read inside a `Draw` callback; pass a map built once, never one per frame. `theme/palette` is v0.2.0's album `palette.ts`: OKLCH steps, the sleeve surface one tone step off the ground, 4.5:1 text pairs, the accent (chroma ≥ 0.06) and `ensureContrast`/`AccentOf`, from Apple's `services.ArtworkColors` (`bgColor`, `textColor1..4`) and `Header.Colors`; `palette.ForAlbum` gives a `Sleeve` and an optional `Accent`, whose `Overrides()` are the maps for `Scope`. `Themes` there equals tokens.json for the six tokens it checks against (a test). `features/album/colours.go` builds them once per cover, theme and layout (cached on the page's state) and `body.go` applies the accent to the page and the sleeve's tokens to the sleeve.
- `theme.ReduceEffects()` is the setting (no backdrops, solid surfaces), `theme.ReducedMotion()` the settings or the desktop's preference; the kit skips its transitions under the latter.
- `theme.Icon("play")` returns a Lucide icon (ISC, `theme/icons`, the version in its README) by its kebab-case name; the names v0.2.0's code used (`ChevronRight`, `Loader2Icon`) resolve through `icons/ALIASES.txt`. `theme.Glyph(c, name, size, theme.GlyphOpts{Color, Inherit, Filled, SVG})` is the one seam for an icon that macOS draws as an SF Symbol (MyGo's `plugins/sfsymbols`): on macOS (`symbols_darwin.go`) a name in `theme`'s Lucide → SF Symbol map (`symbols.go`, `SymbolName`; docs/design.md, "Icons") is a symbol, at the Regular weight and its natural scale over 1.2 times the glyph's box (the box itself is the Lucide icon's), with `.Fill()` for `Filled` and the Lucide icon as its fallback; every other name, and every name on Linux and Windows, is `ui.Icon` of the Lucide icon. A symbol takes no text colour, so `Color` is always given: `Inherit` says it is only the colour around the glyph, which the Lucide icon then keeps taking (with its button's colour transition). The glyph is decoration as an icon is: the symbol's own image name ("play.fill") is cleared, so a button reads its label once; name a glyph that means something with `Role(ui.RoleImage).Label(…)`. `kit.Button`, `PlayButton`, `MenuItem` and the palette draw their icons through it, as do the direct sites of mapped or caller-chosen icons; an icon that is never mapped stays a plain `ui.Icon(c, theme.Icon(…))`. `theme.RegisterFonts()` registers Schibsted Grotesk (variable TTF, SIL OFL 1.1, `theme/fonts`) before the first window opens.

## The kit

Components are functions taking the `*ui.Context`: `kit.Button(c, label, kit.ButtonOpts{…})` returns the element, so `.Clicked()` reads as MyGo's. Give repeated elements a stable key, `c.Key(id)`. The kit's components follow.

- **Button**: `Default` (ink-filled), `Secondary`, `Ghost`, `Outline`, `Link`, `Play` (round amber) and `Destructive`; `SizeXS` (24), `SizeSM` (32), `SizeMD` (36), `SizeLG` (40); icon-only when the label is empty (a square at the size's height, named by `A11yLabel`, which is also its tooltip unless `Tip` says another); `Pressed` makes it a toggle (`Quiet` keeps its colours), `Filled` draws the solid play, pause, star and thumbs-down glyphs (on macOS the symbol's `.fill` variant, through `theme.Glyph`), `Muted` is the quiet ink of the rating buttons. A disabled button is MyGo's 50% (the disabled Play disc keeps `--hover` and faint ink: `DimDisabled(false)` turns the dimming off for it, so it is right over a cover wash too). The face eases over 120 ms (the `feedback` motion) unless motion is reduced; the focus ring is MyGo's, in the ring token, on keyboard focus only. `IconButton(c, icon, label, opts)` is the icon-only shorthand; `PlayButton(c, label, size)` the bare amber disc tiles use.
- **Artwork** shows a DTO's art URL (`/art/<key>/…`) or an Apple template at an exact size. `ArtLoader` (built by the app over `artwork.Cache`) resolves the URL to its template with `artwork.Cache.Template`, asks for the cover at `size × scale` device pixels (the scale of the window the view builds in: each window learns its own from its paints, so the mini player on a screen of another density gets covers of its own size once it has painted; its first pass asks at the scale painted last), and decodes it with `ui.DecodeBitmap` on worker goroutines; the result reaches the main thread through the Poster, and `Bitmap.ReleasePixels` drops the CPU pixels once the cover has been drawn twice. Until then, and when it fails, a `--hover` square with a 40%-ink glyph shows; a failed cover is asked for again after 5 s and 30 s. The 1px line at 6% ink (`ArtOpts.Edge`), round (`Round`) and non-square (`Aspect`) boxes follow `docs/design.md`, "Artwork". Covers are kept up to a count (800) and a weight (`maxArtBytes`, 96 MiB: each cover's decoded pixels and the JPEG its bitmap keeps to decode them again), and the least recently asked for are dropped; the count alone let a scroll through a library's whole Albums grid keep every cover (239 MB of Go heap at 2x for 739 albums). A cover a window's current pass asks for is never dropped, so a page that wants more than the weight at once keeps it rather than decoding what it shows again.
  Loading is parallel and prioritised: 16 covers are in flight at once (their downloads share HTTP/2 connections, `artwork.Options.Fetches`) with one decode per CPU at a time, and the workers take the most wanted cover first (`artRank`): covers whose box showed in the last frame (`Element.InView`), then the rest of the page (below the fold, a long list's overscan), then covers only prefetched (`kit.PrefetchArtwork`; a long `CoverGrid` prefetches the two rows past its built ones, a shelf its next row while it is on screen, and Discover's hero its next card), each in the order asked; a prefetch never starts while a cover on screen is being worked on. A pass of the view (the builds between two paints; `ArtLoader.Pass` in the app's root view, else a window's first `Artwork` after a paint) that was painted without asking for a cover calls it off: a queued cover leaves the queue, one in flight has its context cancelled, and the artwork cache stops downloading a source nobody waits for any more. Asking again starts it again.
- **Controls** (`kit/controls_*.go`; every one takes the ring, ink and `--control-line` from the tokens, strings through `i18n.T` with v0.2.0's msgids, and a `Label` for assistive technology):
  - `Tooltip(c, anchor, text)` is an ink bubble with an arrow over MyGo's `TooltipBase` (hover or keyboard focus, Escape hides it first); the delay is 400 ms, the `tooltip` motion token set as `Theme.TooltipDelay` by `theme.Apply` (MyGo's default is 0.6 s). `Badge` (six variants, `Interactive` for an anchor), `ExplicitMark`, `Tag`, `PreviewMark`, `SDMark`, `Badges` (Explicit, Apple's audio labels from `TraitLabels`, extras), `Separator`, `Skeleton` (pulses unless motion is reduced), `ScrollArea` (a focusable `ui.Scroll`).
  - Fields: `Input` (36 high, `--control-line` border, ring border on focus, `Invalid`, `Disabled`), `SearchField` (glass, Clear, Escape), `TextArea` (the multi-line field on Input's face: `Rows`, default 3), `Combobox` (type to filter, Down shows all), `Switch` (default and small, 140 ms thumb), `Select` (`SelectOption`, `SelectLabel`, `SelectSeparator`; a long list scrolls; the check ends the chosen row), `Segmented[V]` (2–4 exclusive choices as a group of toggle buttons, each its own stop of Tab; `Changed` on every click), `Slider` (4 px track, 12 px ink thumb always drawn, 4 px ring on keyboard focus; `Vertical`, `Step`), `ProgressBar` (0..1, negative is the unmoving empty track), `Tabs` + `TabPanel` (default and `Line`, `Vertical`).
  - Header controls report what was asked and leave state and service calls to the caller: `RatingButtons` returns a `RatingAction`, `LibraryButton` a `LibraryAction`, `PlayButtons` reports `(play, shuffle)`.

A tile is one focusable source (click or Enter opens; Ctrl/Shift+click select; arrows move; Shift+arrows extend; Ctrl+A; Escape), its play button, motion cover, release badge, explicit mark and `ActionMenus` more button as v0.2.0's; `CoverRow` shows as many tiles as fit in `Rows` rows, `CoverShelf` is a `Shelf` (`See all`, or `ShelfToggle` Show all/fewer in place) over a row. More than 200 rows in a `Pane` are built by row (12 beyond).

- **Drag** (`DragItem`, `DragPayload`, `DropTarget`, `DropOn`, `DragActive`, `DragPinned`, `DropIndex`): `shared/dnd` over MyGo's value drag. A press becomes a drag after 6 DIPs; the item stays drawn by a twin while MyGo's copy of it is empty, and the ghost card (artwork, title, caption saying what a drop does) is built in an `Overlay` 14 DIPs right of and 10 below the pointer, flipped near the window's right edge. Targets accept or decline, describe the drop and get `Hover`; a declining inner target lets the nearest accepting one around it take the drop. Escape cancels; the scroll container under the pointer scrolls near its edge (MyGo's, 32 DIPs). One engine per process, main thread only.
- **Palette** (`PaletteSource`, `PaletteSection`, `PaletteEntry`), `Keycaps`, `RankCommands`, `MatchScore`: the command palette's frame, UI only: a dialog 14 % from the top with one combobox field over a grouped list (Up/Down wrap, Enter runs after the dialog has closed, Esc closes and the focus returns), keycaps, hints; the commands feature supplies the sections. `RankCommands` is `features/commands/rank.ts`.
- **Artwork options (media)**: `ArtOpts.Fallback` builds the fallback in place of the glyph (PersonAvatar's initials), `Contain` shows the whole picture at the shape its URL names (a banner stays wide) and decodes it at that size, and `FluidArtwork` fills its container's width at square or 16:9 and decodes for the largest width. `ArtLoader` also loads backdrops (`/art/<key>/backdrop.jpg`, the pre-blurred JPEG from `artwork.Cache.Backdrop`, decoded at its own size) through the same queue, cache and retries.
- **PersonAvatar, Avatar, AvatarGroup, SonaMark**: `PersonAvatar` is a round picture or the person's initials (`Initials`: first letter of the first and last word, whole grapheme clusters; 38% of the diameter, semibold) on one of eight tints (`AvatarTone`: FNV-1a of the lower-case NFC name mod 8, `avatar-N-bg/fg` tokens); decorative. `Avatar` (24, 32, 40 DIPs, muted fallback text, `Badge`), `AvatarGroup` (overlap 8 DIPs, `+n`) and `SonaMark` (amber disc, surface spindle hole) are shadcn's avatar and the brand mark.
- **Backdrop** is a box whose background is the cover's dominant colour at once, then the Go pre-blurred image at 110% fading in over 300 ms (a new source is decoded before it replaces the last), under a solid scrim of the surface or ground token at `backdrop-scrim`; nothing under Reduce effects. It holds its children, which draw over it.
- **MotionPolicy** (`NewMotionPolicy(bus, post, MotionOptions{Files, Setting, Power, Art})`, which the app builds as `Env.Motion`) says whether motion may play: the setting, Reduce effects, reduced motion, battery (`services.EventPower`) and a decoder (`media.Codec`, probed on a goroutine the first time `Allowed` is asked: GStreamer's start-up and plugin scan on Linux never run on the main thread, and motion stays off until it answers; it is "avc" at once on macOS and Windows, where `ui/video` cannot be asked, and a system with no video framework turns it off at the first open); `SetVisible` (window hidden), `Cover` (Now Playing, full-screen lyrics, a modal) and the cover's own `InView` pause playing videos. It owns the decoders: it opens them off the main thread (`media.OpenMotion`: the file straight from `motion.Cache.Local`, no HTTP, the system's player on macOS and Windows, GStreamer's decoder on Linux) and closes those whose view stopped building them (a sweep, as there is no unmount). `Report` is the native `MotionReport` for Diagnostics.
- **MotionCover** is the still `Artwork` with the looping muted video over it, fading in over 300 ms once the player is `Ready` (a system's player loads in the background, so the cover builds the video transparent until its first picture came and the slot is `opening`, not `ready`); the still stays if the video fails (the player's `Err`, which Diagnostics' "Last video" row shows). **TileMotion** (`TileMotion(c, policy, motion, size, opts)`) is a tile's motion: the tile says it is hot (hovered or focused; `Focus` marks focus only), the video opens after a 400 ms dwell, one tile at a time (a hovered tile takes over from a focused one; an owner that failed or is no longer built is gone; waiting tiles are woken by the owner's release, nothing polls), at the tile's own size for the scale of `MotionOptions.Art` (`motionPx(size, scale)`, as a cover's, so the rendition is never narrower than the tile draws), and goes when the tile cools; nothing is built at rest. Both draw the video in the still's own box (same size, `Fit(Cover)`, radius and edge), so the motion sits exactly where the still sits, and neither letterboxes, tints nor frames it (Apple's Album Motion Guidelines: `docs/apple-music-reference.md`, "Motion artwork").
- **VideoFeed and VideoSurface** show the playing music video: a goroutine takes the latest picture from `video.Surface`, checks that its planes are whole and hands it to the main thread, which updates one bitmap in place with `Bitmap.UpdateYUV` (the I420 planes as the child sent them, BT.709 limited range, converted by the GPU; the CPU renderer and captures convert as they need it, so no CPU conversion of Sona's own is left, and the main thread only interleaves the chroma planes for the GPU); pictures are not handed over while the view is not drawn. A frame whose planes are shorter than its size says is dropped (`UpdateYUV` panics on one). Memory only, never a backlog. `Restart` forgets the picture and takes only pictures shown from now on (a new queue entry must never show the one before's last picture), `HasPicture`, `PictureSize` and `Pictures` (a count, for stall detection) are what the view reads.
- **GradientText and SweepText** are text with a fill that sweeps along it: the text drawn again over itself clipped to the reached part, then eight slices of a soft edge (half an em); shaped once, painted from the clock. `SweepText` is the word-timed lyric line, shaped in the lyrics' language (the part's: the romanisation's for the pronunciation), as a `Text` with that `Lang` is: Han characters take that language's glyphs and Korean lines break between words (MyGo's keep-all for `ko`); the mini player's sung line carries the lyrics' language the same way. **EqualiserBars** is the now-playing mark: three amber bars moving in three steps (about ten frames a second) only while playing, uncovered and with motion not reduced.

## Testing with `ui.Tester`

`ui.NewTester(view, width, height)` runs a view without a window or a display, in `go test`: `tt.Click("Save")`, `tt.Key(0, ui.KeyTab)`, `tt.Focused(…)`, `tt.Find(text-or-label)` for a box, `tt.Advance(d)` to move its clock (animations, `c.After`), `tt.SetScale`, `tt.SetDark`, `tt.SetPreferences`, and `tt.Image()` for the last frame. Elements are found by their text or `Label`, so every interactive element has a translated label. The patterns the foundation's tests use:

- Views take what they need from a struct (the feature's state), so a test builds the struct and drives `tt` against its view; `theme.Apply(c)` first, `theme.SetMode` for light or dark.
- Off the main thread, tests give `store.Client`, `store.Bus` and `kit.ArtLoader` a Poster that queues funcs and run them on the test goroutine, as the app runs them on the main thread (`-race` is part of `tests`). Store tests move a fake clock (`Client.now`) instead of sleeping.
- A test never sleeps for the UI: it advances the tester's clock. (Fetch goroutines are the exception: poll with a deadline.)
- `internal/ui/uitest` wraps this for features. `uitest.Env(t)` (or `uitest.New(t, opts...)`, whose `Harness` also hands out the database, the engine and the clock) returns a `module.Env` over a real `services.Core` on a temporary SQLite library seeded with the synthetic fixture (`uitest/fixture`: 24 invented albums by 12 invented artists, three of them singles and three explicit, their songs and three playlists; never Apple's data), `playback/fakeengine` under the real coordinator, an artwork cache whose HTTP serves generated covers (`fixture.CDN`), a Poster that queues what goroutines post until the test drains it (`Harness.Main`), and a fake clock (`Harness.Clock`). Options: `Albums(...)` for a library of your own, `Empty()`, `Bare()` (no services: the bus, the playback mirror and the artwork loader only), `Dark()`. `h.Tester(t, view, w, h)` (or `uitest.Tester(t, env, view, w, h)`) is a `ui.Tester` plus `Until(what, cond)` (drains and draws frames until the goroutines delivered, 10 s at most), `Shows(texts...)`, `Drain()` and `Settle()` (frames until the picture stops changing). `Env` sets `MYGO_GPU=0` (the CPU renderer), English, and the light theme, and restores the theme afterwards.
- `internal/ui/uitest/access` reads what assistive technology sees of a `ui.Tester` window (roles, names, descriptions, states, actions; `access.Read`), fails for a control nested inside a button or link, which MyGo reads as one piece and so hides (`access.NoNestedControls`), and walks Tab round the window, failing for a stop that is not on the tree or a trap (`access.TabWalk`). It lives beside `uitest` rather than in it so the kit's own tests can use it. Each feature package keeps its pages' tree, Tab-order, Escape and announcement checks in `a11y_test.go` (`docs/accessibility.md`). Tests click by name with the Tester's own `Click`, which tries every control of that name.

`go test ./internal/ui/...` takes seconds. Golden images are few: `uitest.Golden(t, tt.Image(), name)` compares with `testdata/golden/<name>.png` beside the test, by the mean colour of 8×8-pixel blocks, so another machine's text antialiasing matches but a moved edge, a changed colour or a missing cover does not (a block differs when a mean channel is more than 12 off; the test fails when more than 0.3% of the blocks differ), and `go test ./internal/ui/app -update` rewrites them when a change is on purpose. A failure saves the picture and a diff (differing blocks red) in the test's artifact directory (`$SONA_TEST_ARTIFACTS/<test name>` when that variable is set, as in CI, which uploads it; else `t.ArtifactDir()`, see `go test -artifacts -outputdir DIR`; tests ask `internal/ui/uitest/artifacts` for it, and only when they fail, so passing runs stay cacheable). Golden images are compared on Linux only (Pango shapes the text there; Core Text and DirectWrite place glyphs differently, which a tolerance should not hide): elsewhere `Golden` skips the test with that reason, after the test's behaviour assertions have run. Today: the shell with Albums, light and dark, at 1132×1253 (`internal/ui/app/testdata/golden`).

## The development loop

`devenv shell -- dev` runs `cmd/devloop` on `./cmd/sona`; `devenv shell -- gallery` runs it on `./cmd/uigallery`. The loop builds the target with `-tags dev,sqlite_fts5` into `bin/<name>-dev`, starts it, and watches `internal/`, `cmd/`, `build/`, `go.mod` and `go.sum` by polling (100 ms). A change to a file of a package the target is made of (`go list -deps`, so a sibling tool's files build nothing) builds again while the old app keeps running; a build that succeeds quits the app with SIGTERM (so it saves where it was), installs the binary and starts it with the same arguments and environment; a build that fails prints the compiler's output and leaves the app alone. `r` builds and restarts at once, `q` quits the app and the loop; the app quitting by itself (Quit from the tray or MPRIS; closing the window only hides it to the tray by default) ends the loop, a crash waits for the next change. Arguments after `--` go to the app; `-ldflags ""` keeps DWARF for a debugger. `devloop` prints how long each restart took, from the save to the app's `startup: first paint`.

- **Speed.** A restart is the compile of the changed packages and their importers (about 1 s for a change under `features/library`), the link, and the start. The link is cgo's: SQLite and the playback host's C++ shim make Go call the system C++ compiler, and before linking Go asks it half a dozen times whether it knows a flag by linking a trivial program (0.3 s each under nix's compiler wrapper, 1.5 s in all). `devloop` builds with `-ldflags "-w -extld=<itself>"` and answers those probes from a file after the first time (`os.UserCacheDir()/sona-devloop/extld`); `-w` drops DWARF (another second).
- **Restore** (`internal/ui/devstate`, `app/restore_dev.go`; dev builds only). When the app quits it writes `$XDG_STATE_HOME/sona/dev-restore.json`: the route and query, the scroll offset of each page, the flags pages registered (`devstate.Flag("queue.open", &q.open)`, for an open overlay or aside) and the window's size and place (Wayland gives no position). The next start applies it before the first frame, so a restart lands on the same screen and offset: a page calls `devstate.Scroll(c, &pos)` before the container that tracks `pos`, and the offset is asked for until the page is tall enough (its data arrives after the first frame). `SONA_DEV_FRESH=1` ignores the file. Another dev-tagged program calls `devstate.SetName("<name>")` first and gets `dev-restore-<name>.json` (the gallery's is `dev-restore-uigallery.json`), so it never overwrites the app's.
- **Two worktrees side by side.** In a dev build, `SONA_DEV_INSTANCE=<name>` (letters, digits and underscores kept, the rest become `_`; `internal/devinstance`) writes the restore file to `sona-<name>/dev-restore.json` and appends `.instance_<name>` to the single-instance D-Bus name (`dev.coredev.Sona`) and to the MPRIS name (`org.mpris.MediaPlayer2.sona`), so each worktree has its own primary instance, `sona status` and the other commands reach the one the same variable names, and `playerctl -p sona.instance_<name>` the right player. A production build ignores the variable. Data, settings and the cache are not separated: give each worktree its own XDG dirs, as AGENTS.md says.
- **Live tokens and catalogues.** A dev build reads `internal/ui/theme/tokens.json` from the source tree at start (`SONA_SOURCE`, which `devloop` sets, else where the compiler found the source), watches it and `internal/ui/i18n/locales/*.po`, and calls `theme.Reload` or `i18n.LoadCommunity` on a change: the next frame shows it, no build and no restart. An invalid file is logged and the old tokens stay. `devloop` does not build for these files.
- **The gallery** (`cmd/uigallery`) shows every kit component, light and dark (the toolbar's switch), at a scale (the toolbar's slider, 50–200 %), with knobs; the sections list in the sidebar. A kit PR adds its own `cmd/uigallery/<area>.go`: `func init() { register(section{name: "Tabs", build: func(c *ui.Context, g *gallery) { … }}) }`. `g.dark` is the mode and `g.art` a `kit.ArtLoader` that serves a generated cover for any `src` (`coverURL(n, delay, fail, nonce)` makes one that loads late or fails). `helpers.go` has `text`, `heading`, `note`, `labelled`, `knob` and `panel`. Under `devloop` the gallery restarts on its section, mode and window like the app.

## Conventions

- Views are methods on the feature's state struct; build values (`ui.Element`) are never stored (`go tool mygo vet internal/ui` in `check`: it takes the directory, and runs `go vet` and MyGo's analyzers over everything under it).
- Off the main thread: service calls, decoding, file I/O. Back through `store` or the Poster only.
- Logs never carry tokens or personal data (AGENTS.md).
- Performance rules (AGENTS.md "Linux Performance Rules"): no layout, text shaping or image work per frame; `Scroll` and an own virtualisation for long lists; artwork at the exact size, off the main thread; backdrops are pre-blurred in Go.

## The app shell (`internal/ui/app`)

`main` builds the core, then `mygo.App.WhenReady` calls `app.New(Options{Core, Settings, Bus, Windows, Art, Log, Version, Dev, Icon})` on the main thread; `mygo.App.Run` returns when the window closes and `App.Close` releases the art loader and writes a pending window size. Two things exist before the core because the services keep them: the event bus (`store.NewBus`, `Deps.Emit`: events emitted before the window exists queue and flush in order) and the window control (`app.NewWindows`, `Deps.Windows`, `Focus` and `Focused`: `Windows` implements `services.Windows` for the main window and does nothing until `New` attaches it). `Deps.Clipboard` is MyGo's clipboard (`mygo.Clipboard.Write`), `Deps.OpenURL` is `mygo.Shell.OpenExternal`.

`New` builds, in this order: the `Env` (the bus with `Window.Update` as its Poster, `store.Client`, the `store.Playback` mirror, the `kit.ArtLoader`, `Env.Post`: the same Poster, for a goroutine to hand a result to the view; with services, `Env.Queue` and the one `Env.ItemStates`), the modules of `modules.go`, the router, the shortcut dispatcher, and the main window (the remembered size and maximised state from `config.Settings.Window`, 940×600 minimum, title "Sona", the inspector only in a dev build with `SONA_INSPECTOR=1`). Then, on the main thread, it follows the settings (theme mode, reduce effects, the language), seeds the mirror from `PlaybackService.State` and `Queue`, and runs every module's `Init`.

- **Motion.** `New` builds `Env.Motion` over the motion cache (`Options.Motion`, `Deps`' `motion.Cache`), the Motion artwork setting (read live: `followSettings` keeps it current), `MotionService.Power` and the art loader. The window's show, restore, hide and minimise events call `SetVisible`; at the end of every frame the shell holds one `Cover()` while a `Layer` slot is open, an `Overlay` slot is open or any `kit.Dialog` (the confirm host and the palette included) was built (`kit.TakeDialogsBuilt` counts them), so the videos under a modal pause. `MotionService.Report` gets `Env.Motion.Report()` for the bug-report bundle: the shell sends it whenever it changed, from three seconds after the first frame (building it starts the decoder probe, which must not compete with the first paint). `App.Close` closes the policy and its decoders.
- **Routes and the start page.** Every module's `Routes` are matched in registration order by one `ui.Router.View`; a path nothing matches replaces itself with the start page. The start page is `Options.StartPath` when given, else `Desktop.StartPage` when a module registered exactly that route, else the first of `config.StartPages` (v0.2.0's choices, Home (`/`) first) a module registered, else the first sidebar link (primary, then library, then footer, by `Order`). The window opens on `Desktop.LastRoute` instead when `Desktop.ResumeLastRoute` is on and a module still shows that route, and on `/welcome` at a first start (`Options.FirstRun`), which opens the first-run setup and replaces itself with the start page. **Route memory:** a route that stays a second (`routeSaveDelay`, counted on the frame clock) goes to `DesktopService.SetLastRoute`, which keeps it only while resuming is on; `/welcome` is never kept. **Deep links:** `services.EventAppOpen` (the command line, a second launch, and on macOS `mygo.App.OnOpenURL`, registered only in `cmd/sona/openurl_darwin.go`: MyGo's launch-argument scan would deliver each launch link twice on Linux and Windows once URL schemes are declared) pushes v0.2.0's `routeForOpen` route (album, a song within its album `?song=`, song, artist, playlist, music video, station, curator) when a module shows it, and is ignored otherwise.
- **Page changes** fade (`ui.TransitionFade`, 150 ms), as MyGo's default does with less motion. Its default otherwise slides a page nested in the one before by path, and For you is `/`, which every path nests in: every change from or to For you slid, while most others faded.
- **Layout**: the sidebar (232 DIP, `surface`; the mark and "Sona" in its 48 DIP header, the primary links, then a scrolling middle with the "Library" heading, the library links and the modules' `SidebarSection`s, then the `SidebarFooter`s and the footer links) | a 1 DIP `line` | the main column: the top bar (48 DIP, `surface`: MyGo's back and forward buttons on the router, the `TopBarSearch` slot, room to grab) over a 1 DIP `line` over the page row (the routed page on `ground`, the `Aside`s, and each open `Overlay` covering the page, which stays built, hidden, so it keeps its scroll). The `Bottom` slots run across the window under both; a `Layer` is drawn over everything and, while its `LayerOpen` holds, the window under it takes no input. A route or link exists only when its module is registered. A page owns its scroll container.
- **Links** are `ButtonBase` with the link role, active on their page and below it unless `Exact`; the keyboard and the screen reader get them by their label.
- **Shortcuts.** One dispatcher asks MyGo for every chord each frame (`c.Shortcut`), with the user's `config.Settings.Shortcuts` over the defaults, and runs the first shortcut bound to a pressed chord whose `When` holds; an `Unavailable` one takes the key and toasts and announces why. MyGo gives a focused text input the keys it types and a focused button or slider Enter, Space and the arrows first, which is what v0.2.0's `keyAllowed` did by hand. Each link gets `nav.<path>` (`nav.library.albums`): Ctrl+1…9 by position in the primary section, Alt+1…9 in the library's, unless the item names `Keys`. The shell's own is `shell.sidebar` (Ctrl+B). On macOS a focused text field takes Ctrl+B/F/P/N/H/D/A/E/K itself (AppKit's emacs bindings), so the default chords written `Ctrl+X` are bound as `Meta+X`, Command (`platformKeys`, applied to the registered defaults only; labels follow: ⌘, spoken "Command"); a binding the user saved is kept as written. A few commands whose keys are lone letters gain a Command chord on macOS only (`macKeys`), so that the menu bar can show a key for them. Back and forward are MyGo's (Cmd+[ and Cmd+] on macOS, Alt+Left and Alt+Right elsewhere, the mouse's side buttons), not shortcuts of ours. MyGo reports a key held down as presses, so `Shortcut.Repeat` has no effect yet.
- **Rebinding.** The dispatcher rebinds on every `settings:changed` (`dispatcher.rebind`): a saved binding applies at once, no restart. `Env.Shortcuts()` lists every registered shortcut (modules', navigation and the shell's) as a `module.BoundShortcut`: the `Shortcut` and the keys it answers to now, the user's binding or its defaults, in registration order. Settings → Shortcuts and Find a setting read it. Settings → Shortcuts refuses the router's own back and forward keys (Cmd+[ and Cmd+] on macOS, Alt+Left and Alt+Right elsewhere; `routerChord`) with a reason, as it refuses Tab: the router takes them before the dispatcher, so a shortcut on one would never run.
- **The macOS menu bar** (`menubar.go`; macOS only: Linux and Windows draw no menu bar). `buildMenuBar` is a pure function from `menuInput` (`Env.Shortcuts()`, the sidebar's pages, what plays, private listening, whether the history can go back or forward, the sidebar, mini player and full screen) to a tree of `menuEntry`: Sona (About, Check for Updates…, Settings…, Account Settings…, Services, Hide, Hide Others, Show All, Quit), File (New Playlist, Open Link from Clipboard…, Close Window), Edit (the edit roles, which MyGo enables while the focus can act on them, and Find…, which focuses the search field), View (the sidebar, Now Playing, Lyrics, Queue, Video, full screen), Go (Back and Forward, the sidebar's pages in its order, each with the key it answers to now, and the Library pages in a Library submenu), Controls (play or pause, next, previous, skip ahead and back, favourite, shuffle, repeat, volume, mute, Private Listening, Sleep Timer), Window (Minimize, Zoom, Mini Player, Equaliser, Sona, Bring All to Front, the window list) and Help (Keyboard Shortcuts, Command Palette, Report a Bug…, which opens Settings → Diagnostics). `TestEveryShortcutIsInTheMenuBarOrLeftOutOnPurpose` fails when a module registers a shortcut that is in no menu and not on its short list of keys of a page's own (Escape to close the overlay, the lyrics timing). An item runs the shortcut's own `Run` (`invoke`, what the dispatcher runs; the palette is the same), is disabled while its `When` does not hold or it is `Unavailable`, and takes its key equivalent from the keys bound now, so a rebinding in Settings → Shortcuts changes it (`settings:changed` refreshes the bar). A menu takes its key before the window sees it, so a key shown in a menu is run once, by the menu, and the window's dispatcher does not see it. The text fields are MyGo's, not AppKit's, so only a Command chord that no text field edits with is a key equivalent (`macAccelerator`): a lone key (Space, `S`, `?`), Shift or Option with one, and Command with an arrow, Home, End, Page Up or Down, Backspace or Delete, stay the dispatcher's and show no key. So that the Controls and View menus still show keys, the commands whose keys elsewhere are lone letters (shuffle, repeat, Now Playing, Lyrics, Queue) have a second default on macOS, a Command chord (`macKeys` in `shortcuts.go`, added by `platformKeys` after the others). Back and Forward are the router's own (Cmd+[ and Cmd+] on macOS): they are no shortcut of Sona's, so Settings → Shortcuts does not list them and their items show the router's keys as they are. Labels go through `i18n.T`, so they follow the language. `menuBar` writes the model into MyGo's menus (`App.SetMenu`) and, as the playback mirror, private listening, the settings (bindings), the language, the mini player, the sidebar, full screen or the history change, or an item was chosen, writes only what differs (`SetLabel`, `SetAccelerator`, `SetEnabled`, `SetChecked`).
- **History gestures.** Back and forward are MyGo's router's: the top bar's buttons, Alt+Left and Alt+Right (Cmd+[ and Cmd+] on macOS), and the keys `KeyBack` and `KeyForward` (a mouse's side buttons, keyboards that have them, and on macOS the swipe MyGo reports from `swipeWithEvent:`, which AppKit sends for the three-finger choice of System Settings → Trackpad → More Gestures → "Swipe between pages"). The router takes the keys with the focus anywhere, in a text field too; they do nothing behind a modal dialog or layer. The other choices of that setting, "Scroll left or right with two fingers" (the default) and "Swipe with two or three fingers", send scrolling and no swipe, so `kit.Swipe` (the root's `HandleInput`) turns that into the same two moves: a precise (touchpad) scroll that travels 12 DIPs and then at least twice as far sideways as up or down is a swipe, and goes back (fingers to the right; to the left in a right-to-left window, as WebKit mirrors it) or forward (the other way) once it has travelled 120 DIPs, one page per gesture; momentum events never count and a gap of 200 ms ends a gesture where the system sends none. It is on only on macOS, and only while the setting lets a two-finger scroll swipe: the shell reads the `AppleEnableSwipeNavigateWithScrolls` default (`defaults read -g`, on when absent) off the main thread at start and each time the window takes the focus (`refreshSwipe`). A gesture that begins over a container that scrolls sideways and can scroll that way (`kit.ScrollSideways`, which a shelf wider than its box must use instead of `ui.ScrollHorizontal`) is the container's. While a module `Overlay` (Now Playing) is open, a change of the page's location (the query too: a second search is another entry) closes it (`Overlay.Close`): the page that came is behind it. MyGo gaps this works around, for a maintainer's upstream report: `InputEvent` has no gesture phase (began, ended, momentum began; `NSEvent.phase`), so a gesture is inferred from the event times; it has no `isDirectionInvertedFromDevice`, so the direction is right for macOS's default "Natural scrolling" and swapped with it off; there is no API for `NSEvent.isSwipeTrackingFromScrollEventsEnabled`, the system's choice of swipe gesture, which Sona reads from the defaults instead; and `Tester` cannot send momentum events (`Scroll` is precise, `Wheel` is not, and neither sets `Momentum`), so momentum is tested on `kit.Swipe` directly.
- **First paint.** The first frame the root paints calls `SystemService.FirstPaint()` once, off the main thread, which logs `startup: first paint` (`since_start_ms`) and opens the network gate.
- **Language.** The Language setting (else the system's languages, the first that Apple Music's translations cover to `i18n.SelectableShare`) is looked up with `TranslationsService.Apple` off the main thread and shown through the Poster (`SetApple`, `SetLocale`); a new `EventAppleTranslations` or a changed Language setting chooses again.
- **Window size.** The main window's `OnResize`, `OnMaximize`, `OnUnmaximize` and full-screen events feed `observeWindow` (v0.2.0's rule: the size is only taken while the window is neither maximised nor full screen, so un-maximising returns to it); a change is written to `Settings.Window` half a second after it stops, and on close. Wayland gives no position, so none is kept.
- **Windows and the tray** (`windows.go`, `tray.go`, `shell.go`). `Windows` (services.Windows) runs every call on the main thread (`mygo.RunOnMain`). Closing the main window or the mini player (`OnClose`) hides it and keeps playing when there is a tray and Settings → General says "background"; otherwise, and always without a tray, it quits. `Windows.Quit` (the tray, MPRIS Quit) and any app quit (Cmd+Q, the app menu, SIGTERM; `OnBeforeQuit`) let every window close. `ShowMain` (the tray, MPRIS Raise, a second launch, the Dock icon through `OnActivate`) hides the mini player and shows, restores and focuses the main window. The mini player (`Slots.Mini`, the first module's) is a 420×132 DIP frameless, fixed-size, always-on-top window that never maximises, made on first use and then hidden, never destroyed; `ToggleMini` shows it in the main window's place, and `post` redraws it beside the main window while it shows. The tray (`mygo.NewTray`, made before the window; libayatana-appindicator3 on Linux, a template menu bar icon on macOS) is v0.2.0's menu: the song, Play or Pause, Next, Previous, private listening, Show Sona, Mini Player, Quit Sona, written again on `playback:state`, `private:changed`, the mini player's state and the language. Its items are in title case on macOS, as menu bar items are ("Not Playing", "Private Listening"), and in sentence case on Linux and Windows ("Not playing", "Private listening"): `trayState.titleCase` (set from `runtime.GOOS`) picks between two messages of the catalogue, the way the mini player's "Mini Player" and "Mini player" are two, so a translation of either is kept and neither is derived from the other. A primary click on the icon shows Sona (`OnClick(ShowMain)`: KDE's click, GNOME's double click), and the icon is destroyed on `OnWillQuit`. `Windows.HasTray` is `Capabilities.Tray`: MyGo reports a tray whenever libayatana-appindicator3 loads, so on GNOME without the AppIndicator extension the icon is invisible and a `--hidden` start stays invisible until a relaunch or MPRIS Raise. `Options.Hidden` (`--hidden`) creates the window hidden when there is a tray: the network opens at once (no first frame comes), motion and `Env.Window.Focused` start off. **Title bar:** `windowchrome.Platform.Resolve` of the Title bar setting picks, as the window is created: macOS's buttons inset (`TitleBarHidden` with `TrafficLightPosition`, centred on the 48 DIP top bar); "sona" a hidden title bar with MyGo's window buttons in the desktop's layout (`TitleBarHeight` 48); "sona-no-buttons" the same with `HideWindowButtons`; "desktop" the desktop's own (Automatic is the desktop's on tiling compositors, unknown desktops and KDE Plasma under Wayland, where KWin decorates a window whose title bar is hidden). With a hidden title bar the top bar and the sidebar's header drag the window (`DragWindow`, a double click maximises) and keep `c.TitleBar()`'s room for the buttons, swapped by direction (`PaddingStart`/`PaddingEnd`; the video view's header does the same and drags the window while it is the top strip). The mini player's Close goes on the side `gtk-decoration-layout` puts it (KWin's kwinrc first on KDE; read through GTK in `cmd/sona/gtklayout_linux.go`). **`Env.Window`** follows the main window's `OnFocus`/`OnBlur` and full screen, with a redraw on each. **Status banner** (`banner.go`, v0.2.0's StatusBanner): one `RoleStatus` line under the top bar for the keyring waiting or unavailable (with `account.KeyringRetry`), a token Apple stopped accepting (Sign in), Apple refusing Sona (Diagnostics) and offline. MyGo's now playing stays unlinked on Linux, where MPRIS is Go's only player; on macOS and Windows Go's `internal/nowplaying` drives `mygo.NowPlaying` (media keys, Control Center, the volume flyout), wired in `cmd/sona/nowplaying_desktop.go`.

### The player bar (`features/player`)

The bar is a `Bottom` slot: 72 DIP, `surface`, a `line` above. The cover (`kit.Artwork`, 48 DIP), the title and the line under it (artist · album; the sign-in, Widevine and error notices; a 30-second preview carries the "Preview" mark), the transport (shuffle, previous, play or pause, next, repeat), the seek bar and the volume. It draws `store.Playback`: the position is `Position()` and ticks every 250 ms while playing; a drag shows where it will go and seeks once, when the pointer lets go. Every command is a goroutine over `services.PlaybackService` (through the small `transport` interface the tests fake); a failure comes back through `Env.Post` and shows as a toast titled by the command and worded by `i18n.ErrorText` of its code. Controls Go says do not apply (the snapshot's `Controls`) are disabled, with the reason (a live station, a station) in the tooltip. Shortcuts keep v0.2.0's IDs and keys: `player.toggle` (Space), `player.next`/`previous` (Ctrl+Right/Left), `player.seek-forward`/`seek-back` (Shift+Right/Left, 10 s), `player.volume-up`/`down` (Ctrl+Up/Down), `player.mute` (M), `player.shuffle` (S), `player.repeat` (R). 
**Queue panel** (`queue_*.go`). `Slots.Aside`: 320 DIP beside the page while `view.queueOpen` and Now Playing is closed (Escape closes it, the focus returns to the bar's Queue button). A 48 DIP header (the heading, `queueTools`: Clear while the user has songs queued, and the AutoPlay toggle, dimmed with its reason where it does not apply) over a list of 52 DIP rows (`queue_row.go`) in sections (the user's songs, then the station's or AutoPlay's, which keep their place), the summary line of what follows the playing song (`summaryOf`). The list is one Tab stop: arrows, Home and End move the focus, Enter plays, Delete removes, Alt+Up and Alt+Down move a user's song, the Menu key and Shift+F10 open its menu; a row drags by its grip and the whole panel is a drop target (`kit.DropOn`: a drop moves a row to the gap, or adds what came from anywhere, songs, videos, albums and playlists). Every change goes through `Env.Queue` (`kit.QueueCommands`), the one place that asks before replacing a long queue.

**Playing item's menu** (`playing_menu.go`, `kit.PlayingTarget`/`PlayingItem`, the one mapping a queue row's drag payload uses too). Right-click, Shift+F10 and the Menu key on the bar's cover, title and artist, Now Playing's cover, song copy and artist/album links, and the mini player's cover and title/artist open the action menu of the playing entry: the one a row of that song opens (`kit.ActionMenus` over `Env.Actions`), by kind (a song's, a music video's, a live station's; none while nothing plays). Now Playing also has a "More for <title>" menu button (`RoleMenuButton`, `Expanded` while open) in its actions row, the way in without a pointer; the bar has none (no room: Shift+F10 on the cover). The entry is not in a list, so the menu has no container actions. Each surface owns one `ActionMenus` drawn by a single `Popup` per frame. MyGo hands a right-click to the innermost interactive element, so a clickable child (the bar's cover button, the title and artist `ui.Link`s, Now Playing's `outLink`s) calls `Row` itself. `ActionMenus.Navigate` makes a page a chosen action opens close Now Playing first; `ActionMenus.Before` lets the mini player bring the main window back before any action but a queue one (its router, dialogs and toasts are the main window's). The mini player's window is the drag handle, so its cover and title take only the secondary press (`HandleInput`, never `RightClicked`, which would make them interactive and stop the drag); its keyboard way in is Shift+F10 or the Menu key with the focus in the window, on the root.

**Sleep timer** (`sleep_timer.go`). The moon button and its radio menu stop playback in 15, 30, 45, 60 or 120 minutes, at the end of the song or of the queue (`PlaybackService.SetSleep`, fading out over the last 10 seconds). The timer is Go's (`PlaybackState.Sleep`): the button reads it, filled while one runs and showing the minutes left, and ticks on the minute boundary of the countdown.

**Rating** (`rating_buttons.go`). Favourite (and Suggest Less outside the compact bar) of the playing song, through `Env.ItemStates` (`kit.RatingButtons`: a change shows at once, Go's answer replaces it). Nothing is drawn for what has no song to rate: live radio, a music video, a song outside Apple Music. The favourite shortcut reads the state off the main thread first, then rates or undoes.

**Announcer** (`kit.TrackAnnouncer`). Tells screen readers, politely and once, that a new track plays (`Now playing: {name} by {artist}`, "a preview" for a 30-second clip) and, once per track and code, that it cannot play; play and pause are never announced. The bar and the mini player each hold one, as only the window that is shown is read.

**`kit.SliderCommitted(sl)`.** True once the user has finished changing a slider: the frame after the pointer let go of it, wherever the pointer is (a drag that drifts off the thin slider is still held), or the frame of a key's change. The seek bars (the bar, the mini player, the video view) seek on it, so a drag seeks once.

**`store.Playback.Unmuted()`** is the volume an unmute returns to (`SetUnmuted` remembers the last non-zero one; `DefaultUnmuted` 0.8 before any mute). The bar's mute button, the M key and the video view share it, as v0.2.0's one `unmuted`.

### Now Playing and lyrics (`features/player`, `lyricsync`)

Now Playing is the player's `Overlay` slot (open while `view.overlay` is `overlayNowPlaying`; the panels' shared state is `view.go`: the overlay, the pane, the queue beside the page, `fromRoom`) and full-screen lyrics its `Layer` (`LayerOpen`: `overlayRoom` with a song that has lyrics; the window behind is inert and the layer's wrapper takes no input while closed). Both are built only while open, so scroll and focus start again on each opening, and the view closes itself when the queue is cleared. Keys: `L` (lyrics, hidden while a music video plays), `N`, `V` (the music video view, `Env.Video`), Escape (scope `now-playing`: room to Now Playing to the page), `Shift+L` (full screen), `[` `]` `\` (timing), with v0.2.0's IDs.

- **Layout** follows the view's own box as last drawn (`measureLayout`, `nowPlayingLayoutFor`): stacked (the song as a header over the pane) under 880 DIP, else the cover beside the pane with a 56 gap; the cover is 168 stacked, else `min(width ≥ 1000 ? 400 : 320, height ≥ 720 ? 400 : height ≥ 640 ? 320 : 240)`; the column is at most 1280 wide. The wash is `kit.Backdrop` (tone ground) as an absolute `PassThrough` sibling; the cover is `kit.MotionCover` over the one rendition asked for at 420 DIPs (`Overlay` set, so it plays while the view covers the page; 840 px at 2x, so Apple's 960 px picture, never narrower than the largest cover) when `Env.Motion` allows motion and the album has some (`MotionService.Album`, cached an hour, never asked while motion is off), a music video's is a 16:9 `FluidArtwork`, a local broadcaster's is the art of the song on air. The song copy, the live station lines (the programme from the radio page's `["radio","station",id]` query), the broadcaster block, Favourite and Suggest Less (the `rating` hook), "View credits" and the artist and album links (only where `Env.HasRoute` knows the page) belong to the Now Playing view (`nowplaying*.go`). The tabs are `ui.TabsBase` (one Tab stop, arrows, Home and End); a station, a music video or a song outside the catalogue has only Up next (a heading), whose body is the queue panel's list, summary and tools (the `queueView` hook the queue code sets; the pane is empty until it does).
- **Lyrics data** is `store.UseLyricsFrom` over `LyricsService.Lyrics` (the one cache `store.KeyLyrics` shared with the song page, always a `services.Lyrics`, never stale: a provider change invalidates the prefix; a song with none, `not_found`, is cached as empty lyrics, not an error asked again every five seconds). The translation and pronunciation choices are `config.Settings.LyricsView`, read from the settings cache (`store.UseSettings`) and saved through `SystemService.SetLyricsView` off the main thread (an export leaves them out); the per-song timing offset is in memory for the session and shared by every window (`lyricsync.Session`).
- **`internal/ui/lyricsync`** is the pure timing logic of `lyrics.ts` and `lyric-words.ts` with their tests: the sung line, rests and verses, the voices of a duet, word progress, `NextChange`, `Shown` (a line under the translation and pronunciation choices). No UI, so the mini player's line can use it.
- **The sheet** (`lyrics_sheet.go`, shared by Now Playing and the room) is a `ui.Scroll` of verses of lines: a synced line is a button that seeks to its begin plus the offset (one Tab stop; Up, Down, Home and End move between lines), a plain one a paragraph. The view is built again only when the sung line changes (a `c.After` for the next line or rest); word-timed texts are `kit.SweepText`s shaped once per line and width (one per part and line, shaped again when the width changes) and painted from the clock in a `Draw` callback. That callback asks for the next frame only while a word is filling; between words, after the last and before the first it sleeps with `Painter.After` until the next change (a word beginning or ending, the line ending, the voice resting). The Go side of a frame is 0.2 ms (no build, no layout, "painted again"); what a frame costs is the window's presentation, which on a CPU rasteriser (llvmpipe in a VM or a headless session, `MYGO_GPU=0`) is proportional to frames a second (60 took 50% of a core, 30 took 29%). So the fill is painted at the display's rate (`Painter.AnimationFrame`) where `Painter.Accelerated()` says a GPU draws and at 30 a second (`AnimationFrameRate(30)`) where the CPU does. v0.2.0 filled only held notes (600 ms) at 12.5 fps because every WebKit frame repainted the window: the native sweep fills every word, as the spike did. Under reduced motion the words are zero-length, so each lights whole as it begins, and the next change wakes the view instead of frames. The reading band (14%–72% of the sheet's height) holds the words still: when the anchor line leaves it the sheet turns to put the anchor's verse (or the line, when the verse is too long) at the band's top, jumping the first time and under reduced motion, else `ScrollTo(…, Smooth)`; a scroll the user made (the offset moved with no glide of ours) or an arrow key keeps it still for 4 s.
- **Full-screen lyrics** are the same sheet at room size (`roomLook`: `clamp(36, 4.4vw, 84)` bold in a 24 ch column, 7vw of side padding, 12% fades), lines as paragraphs, over a footer strip with the cover, the song, the timing nudge and Exit full screen. They put the window in full screen through `Env.Video.SetFullscreen` (the video view's own window binding, so no second hook) and leave it only if they entered it.
- **Focus on close.** The bar's cover, Lyrics and Show video buttons are the openers of what they open (`view.opening`, `ui.Handle`s bound in `bar.go`): closing Now Playing (Escape, Close, a toggle) puts the keyboard focus back on the opener when it was inside the view (`returnFocus`, called by the bar every frame, takes its request back a frame later so a control that is gone never takes the focus when it returns); a view a key opened has no opener and leaves the focus with the page. Full-screen lyrics close into Now Playing, on its Full screen button; the queue beside the page returns to the bar's Queue button; the video view's opener is `store.VideoView`'s: a Play control that opens it is bound to a handle (`kit.CoverPlay.RunFrom` gets the tile's own, `kit.PlayButtonsOpts.Bind` takes the page's, `kit.ItemPlayers.PlayItemFrom`/`PlayVideoFrom` and the video player `RegisterVideo` pass it on) and the view calls `OpenFrom` with it, so closing the view returns the focus to that Play button.
- **Tests**: `lyricsync` has its own timing tests; the player's `nowplaying_test.go` runs the views over `uitest` with a fake lyrics source: the layout and cover policy, panes, loading, not found and failure with retry, the sheet following the line, the user-scroll hold, click to seek under an offset, the timing nudge and reset, translation and pronunciation, keyboard between lines, the room, Escape levels and golden images (light and dark). `NP_EVIDENCE_DIR=<dir> go test ./internal/ui/features/player -run Evidence` writes the PR's pictures.

### The mini player (`features/miniplayer`)

`Slots.Mini` is the whole content of the shell's second window (about 420×132 DIP, frameless, always on top, created hidden on first use). The root is the window's handle (`DragWindow`) over the cover's wash (`kit.Backdrop`): the cover fills the window's full height (132 DIP) at the leading edge with no margin; beside it a text column (12 DIP from the other edges) holds the title (16/22) with the window's own buttons trailing (Open Sona: `DesktopService.ShowMainWindow`; Close mini player: `CloseMiniPlayer`; Close is outermost on the side the platform puts it: `WindowControls.Native == "inset"` or "close" in `Start` put it first, before the title), the artist, the third line, and a foot row with the time left (or a Live marker for a live station) at the start and the transport (Previous, Play or Pause, Next, with the reasons of `kit.ControlUnavailable` as the bar says them) at the trailing side. Progress is one seek slider, a 2 DIP hairline along the whole foot of the window (over the cover too, amber on a 12% ink track) whose hit area is 12 DIP high and which grows to 4 with a thumb under the pointer and while keyboard-focused; a live station has none. It is a local `ui.SliderBase`, with the same Seek label, value text, arrow keys and commit-once-on-release as the kit slider. It mirrors `store.Playback`, sends the bar's commands through `PlaybackService` off the main thread and holds its own `kit.TrackAnnouncer` (the main window's bar is not built while it is hidden).

The mini player has no room for toasts: a failed command replaces the third line for four seconds ("Couldn't skip: …", announced once; a sign-in failure says to sign in to Apple Music in Sona). The third line is the notice, else the line being sung (`lyricsync`: the line from `SungLine` on the lyrics clock, its words lit whole in amber as they begin, two lines at most, woken by a timer at the next line, rest or word; the per-song timing offset is shared with Now Playing), else what needs the user or what plays (the album, "Music video", "Live radio"). The module also adds the player bar's Mini player button (`Env.PlayerControls`, order 30; `DesktopService.ToggleMiniPlayer`) and the shortcut `miniplayer.toggle` (Ctrl+Shift+M, "Show the mini player", View). The shell's window calls have no error to return, so a call that panics is the failure.

### Account side: private listening, Widevine, updates, reminders and motion

Five v0.2.0 modules whose state other features read. The shared parts sit where features may import them: `store` (`UsePrivate`, `UseCDM`, `UseUpdates`, `UseReminders`: queries under the keys `private`, `cdm`, `updates` and `reminders`, never stale, kept current by the owning module's events; `PrivateForced`, `CDMProgress`, `CDMCanRetry`, `ReminderFor`; `Peek` reads a query without fetching and `SetIfEmpty` writes a snapshot only while nothing newer is there), `i18n` (`CDMProblem` and `CDMFailedState` word the failure codes of `internal/playback/cdm`, `FormatPercent`) and `kit` (`SetPrivate`, `RetryCDM`, `SetReminder`, `RemindButton`: the service call off the main thread, a toast titled by what was attempted and worded by the error code). The account menu, Settings, the setup, the player bar and an album page use those without importing the five packages.

- **Private** (`features/private`). `private:changed` fills the mirror; a snapshot only fills it while it is empty (an event that lands first wins). The player bar's pill is added to `Env.PlayerControls`: a ghost 28 DIP toggle with the hat glasses, a muted glyph alone when off, and when on a chip with a 1 DIP dashed `control-line` outline ("off the record"; the element's own `BorderDashed`) holding the glyph and "Private" in ink, no fill (never amber), the word from 1100 DIP of window width and "Private (development build)" from 1280. Forced by `SONA_PRIVATE=1` or not yet known it stays focusable and does nothing (the tooltip says why; unknown is dimmed). The command `private.toggle` (playback group, no keys, bindable) is unavailable until Go reports the state and while forced.
- **CDM** (`features/cdm`). `cdm:status` fills the mirror and refreshes the `diagnostics` queries only when the state, version or code changed, not on a progress step. The notice in `Env.PlayerNotice` is the line under the title while the song waits: "Waiting for Widevine to download" followed by a 48×3 DIP meter (`kit.ProgressBar`, empty while the size is unknown) and the percent while downloading, a 6 DIP `danger` dot and "Couldn't get Widevine · Retry in Settings" (the failure's words as its tooltip) or "Songs can't play on this computer", a check and "Widevine is ready. Press play to start."; a link to Settings → Playback only once that route exists (`Env.HasRoute`), plain text before.
- **Updates** (`features/updates`). The `SidebarFooter` notice is a slip: a `raised` block (radius 6, padding 10, inset 10 from the sidebar's edges) with "New version" in meta, "Sona {latest}" at 14/500 (the status; assistive technology still reads "Sona {latest} is available") and a full-width ink button, "Install and restart" where `UpdateStatus.SelfUpdate` (macOS and Windows installs; `UpdatesService.Install`, a failure toasts and the notice says "Couldn't install Sona {latest}") or "View" (`UpdatesService.OpenRelease`, a failed open toasts) elsewhere, only while `UpdateStatus.Available`; `updates:available` and `updates:install` (download progress, shown as a bar inside the slip in place of the button; "Restarting into Sona {latest}…" as the slip's line once installed) write the query. Settings → General → Updates words why an install can't update itself (`UpdateStatus.Disabled`: no signing key, not writable) and has the Test versions switch (`updates.prereleases`); Linux packages and AppImages keep updating through their own tools (design: `docs/architecture.md`, "Updates").

### Equaliser (`features/equalizer`)

Down in the filter moves the focus into the "Shortcuts" group, which scrolls with the arrows and Page Down; Up at its top goes back. Escape clears a filled filter, then closes; Close and Escape return the focus. "?" is text in the filter, so a filter holding only "?" is the sheet's own chord and closes it; from the list or the link the chord itself does.
- **Chords and macOS.** A text field keeps macOS's Control letters (Control+K kills the line), so the palette's own chord never reaches the window's handler from its search field there: `kit.Palette.Chords` (set by the module each frame to the keys it answers to) hands them to the field's `OnTextKey`, which closes the palette.
- **Not here.** The mini player's shortcut is `miniplayer.toggle` (`features/miniplayer`). Item actions (`Env.Actions`) are not commands: they act on an item, and v0.2.0's palette listed shortcuts only.

### Playlists (`features/playlist`)

Registered between library and player, as in `modules.ts`. It owns the `/playlist/{id}` page, the sidebar's playlist sections (`Slots.SidebarSection`), the dialogs (`Slots.Aside`: `dialogHost` builds the open `kit.Dialog` and nothing else, so it takes no room) and the playlist item actions (`Module.Actions`: add to playlist for songs, albums, playlists and selections, remove from playlist inside an editable container, pin and unpin per kind, edit details, move to folder, delete from library).

- **State and data.** `playlists` holds `Env`, the `playlistsAPI` and `playbackAPI` seams (tests fake them), `prefs`, `edits`, and the `dialogs`, `sidebar` and `page` states. Query keys are v0.2.0's, under `library` so a sync invalidates them (`["library","playlist-tree"]`, `["library","pins"]`, `["library","playlist-recent-targets"]`, `["library","playlist-suggestions",id]`; a playlist's detail is `["library","playlist",id]` for `p.` IDs, else `["catalog","playlist",id]`; collaboration sits under it). `playlists:changed` invalidates the changed playlists except one being edited here, the tree, counts and library playlists when the tree changed, and the pins.
- **Tree logic** (`tree.go`, tested against `tree.test.ts`): folders before playlists at every level, by Apple's position then name; unknown parents at the top; pinned and non-editable playlists left out of the folder tree (their folders count them); sections Made for you (`pl.pm-` catalogue IDs), Apple Music and own.
- **Sidebar.** Pinned, Made for you, Apple Music, Playlists, waiting for pins and tree so a pinned playlist never flashes in its section. Open folders and folded sections persist in `config.Settings.Sidebar` (`OpenFolders`, `FoldedSections`; v0.2.0's `sona.playlist-folders.open` and `sona.sidebar.collapsed` in localStorage), read at start and saved through `SystemService.SetSidebar` (one save at a time, newest state last; it changes nothing else in the settings). Settings exports leave the key out: it describes this computer's library view. Playlist rows and pinned editable playlists are `kit.DropOn` targets that accept any payload whose items hold songs, albums or playlists (a queue row's payload carries its song and an `Origin`, which is ignored here), describe the drop (“Add to …”) and add through `PlaylistsService.Add`; the Pinned section and the “New playlist” row are targets that exist while a matching drag is on; a drag resting on a closed folder opens it after 600 ms.
- **Dialogs.** One at a time (`dialogs.show` replaces): the add picker (search, recents, groups by folder path, arrow keys), new playlist and edit details (one form), folder new and rename, move to folder. A dialog takes the focus on its second built frame, after MyGo noted what to return it to (an `AutoFocus` in the first frame is remembered as the opener). Deleting a playlist or folder asks through `kit.Confirm`. The cover picker (`covers.go`; *Change cover…* in the item menu of any library playlist, `playlists.cover`, and *Cover* beside *Name and description* in edit mode) is a radio group of option tiles from `PlaylistsService.CoverOptions` (Automatic, None, Your image, Apple Music's nine designs of the playlist's generated cover when Apple generates one, else a line saying why there are none; four columns, `GridNav` with arrow keys, scrolling in a short window), applied at once through `SetCover`; *Choose an image…* runs `UploadCover` (the file chooser lives in the service, `Platform.Files`) and a failure stays beside the button as a status. The covers are Sona's own (`docs/apple-music-reference.md`, "Playlist artwork") and the dialog says so.
- **Page.** Loading skeleton, error with Retry and a link back to Playlists, header (cover, byline, meta line, Play and Shuffle, library and rating buttons, Edit, the actions menu), the songs under a "Find in playlist" field and the track list with an editable container, the empty states, the suggested-songs shelf, featured artists and more-from-curator. Links to other pages render only when `Env.HasRoute` says they exist. Edit mode swaps Play and Shuffle for Done and “Name and description” and shows the editor: a grid of rows with drag handle, Alt+Up/Down, Delete, a 2 DIP drop line and polite announcements. Moves and removals are optimistic (`trackedits.go`): shown at once, sent in order per playlist (`edits.serial`, which also hands each answer to the main thread in that order: the next edit starts only once the previous answer was posted), replaced by Go's answer unless later edits are queued, rolled back by refetching on failure (a conflict says the playlist changed on another device).
- **Sort and find** (`view.go`, catalogue and library playlists alike). The page holds every track, so it sorts and filters in the UI with `viewOrder(tracks, key, desc, query) []int`, a pure function that answers original indices: the songs matching every word of the query (folded, in Name, Artist or Album) in the order of the key (Title, Artist, Album, Duration, or none: the playlist's order), stable, so songs that compare equal keep their playlist order whichever way it runs, and digits read as numbers. A header click cycles ascending, descending, playlist order (`TrackSortState.Toggle`) and is announced; the `kit.SearchField` ("Find in playlist", in a search landmark) shows "N of M songs" while it holds a query, announces its count, replaces the table with a message when nothing matches, and Escape clears it. `page.view` memoises the answer per tracks, key and query. Everything the page does with a song goes through the listed songs or maps back: Play, Shuffle and row activation queue the songs as listed (a query narrows the queue to the songs found); Remove from playlist (`ActionContainer.Order`) and "Added by" use the songs' positions in the playlist, because `RemoveTracks` and `MoveTrack` are positional. Edit mode shows the playlist whole and in its own order: entering or leaving it clears sort and query and hides the controls. The state resets in `page.enter` with the rest of the page's. No "Date added" sort: neither `Song` nor `playlist_tracks` records when a track joined the playlist (`library_items.date_added` is when it joined the library, another thing). No Ctrl+F: the global `search.focus` (`/`, `Ctrl+F`) keeps it, because the dispatcher runs the first shortcut bound to a chord whose `When` allows it (search registers before playlist), a page-scoped Ctrl+F would need a dispatcher rule that page shortcuts win or a `When` on `search.focus` that knows the playlist page (features do not import each other), and the settings page would list the pair as a conflict; the field is a click or Tab away.
- **Collaboration** is read only for `pl.u-` playlists (network, cached five minutes): the byline becomes the collaborators stack, the track list shows who added each song (`addedByRows`: the next unclaimed attribution of the song's catalogue ID), and the Collaborators dialog lists current and former collaborators.

### Search (`features/search`)

The `Search` nav item (icon `search`, primary, order 20), the top bar's search field (the `TopBarSearch` slot, `field.go`) and the routes `/search?q&scope`, `/search/{group}?q` and `/profile/{id}`. The field is a combobox input over `kit.Input` named "Search" (max 520 DIP): suggestions open on focus, click and typing; hints follow typing after 150 ms (`SearchService.Hints` for Apple Music, `Library(term, 3)` for the library scope; five-minute cache, previous data kept while typing); an empty field lists up to six recent searches; Up/Down/Enter/Escape/Tab and hover work as in v0.2.0 (`combobox.go`: `splitMatch`, `moveActive`). `search.focus` (`/`, `Ctrl+F`) focuses it and selects its text. The page (`page.go`) shows the scope switch, Browse categories and recent searches with no query, catalogue sections in Apple's order (Top results as rows, Songs as a `TrackList`, other groups as shelves, "See all" when a group has more) or the library's four lists; the group page (`group.go`) loads pages as its end comes within a screen; the profile page (`profile.go`) shows a listener and the playlists they share. ### Tests

The shell's tests build fake modules and drive the view over `uitest`'s tester (nav entries, clicks, Ctrl and Alt chords, first paint once, the settings' start page and bindings, slots, text fields keeping their keys); a test pins the real module list in v0.2.0's order and that a duplicate module ID panics, and its golden test runs the real modules over the fixture library. The player's run the bar over a fake `transport` on a bare `uitest` Env; the library's over the full Env (`newPageRig`: the real module's routes, actions and subscriptions over a real `services.Core` on the seeded SQLite library, the fake engine, the covers' fake CDN; `uitest.Apple(handler)` signs the Core in to a fake Apple Music account and serves the handler on the harness network at `uitest.AppleHost`, search and concerts tests answer with JSON shaped like Apple's, and `Harness.Opened()` lists the URLs sent to `Env.OpenURL`): every page's data, sort and type in the URL, paging, selection and keyboard navigation, the actions and their toasts, sync events and the sidebar indicator, the gate's states, the play button, empty states. The library's golden images are Albums, Songs and Artists, light and dark. Fetch goroutines are waited for with `Session.Until` (a deadline); everything else advances the tester's clock.

A `uitest` Core is hermetic: whatever the machine running the tests holds (a signed-in keyring, a network, a session bus, Sona's own settings), the services see none of it. `Harness.Keyring` is an empty in-memory secret store handed over `Deps.Keyring`, so the Secret Service is never asked (a maintainer's real Last.fm session is not found). `Harness.Network` is the one `http.RoundTripper` behind every HTTP client the Core is built with: `Deps.Transport` (lyrics and scrobbling under the first-paint gate, the update check without it: it runs only from `OnNetwork` or on request), the artwork cache's client and the auth manager's. It serves the fixture CDN's host and what a test adds with `Network.Serve` or `ServeHandler` (an in-process handler: a GitHub release, say), and fails any other request at once with an `ErrOffline` that names the method, host and path and is a `net.Error` (the services class it as `network`); `Network.Blocked` lists what it refused. `uitest.New` also points the process environment at the test's temporary directory for the length of the test: `HOME` and the XDG directories (what `os.UserConfigDir`, the autostart file and Discord's socket search read; the cache directory is one per user, `<user cache>/sona-tests/uitest`, beside Sona's own and kept between runs (on macOS `$HOME/Library/Caches` of the test's home is a link to it, since `os.UserCacheDir` ignores `XDG_CACHE_HOME` there; on Windows `%LocalAppData%` is it), since MyGo registers the interface font once per process from a file it writes there and fontconfig keeps its cache there), `DBUS_SESSION_BUS_ADDRESS` and `DBUS_SYSTEM_BUS_ADDRESS` at a socket nobody listens on (a D-Bus call fails at once instead of reaching the real bus; the `Platform` the Core gets is empty, so no MPRIS, notification, power or autostart code runs at all), no Discord application and a made-up Last.fm key, so what the Core offers does not depend on the machine. `http.DefaultTransport` is the same `Network` for the length of the test (loopback excepted, for `httptest` servers; restored afterwards), so a client built on `http.DefaultClient` fails fast too. A new service that reaches outside the process takes the seam from `Deps` (`Env.gated`/`Env.transport` for HTTP, `Env.openSecret` for a keyring secret) and never `http.DefaultClient`, `store.OpenSecret` or a platform package directly. The tests in `uitest/hermetic_test.go` cover the scrobblers, the ListenBrainz check, the update check and `http.DefaultClient`; a new service that reaches outside the process adds its case there.

The end-to-end smoke (`e2e/`, build tag `e2e`) is the built app seen from outside. `headless -- go test -tags e2e ./e2e/...` (the devenv `e2e` script; CI job "E2E (headless sway)") starts a headless sway with a private session bus and AT-SPI bus (`e2e/headless.sh`), builds `bin/sona-e2e` with `-tags probe,sqlite_fts5` (MyGo's automation plugin, a fake playback engine and an HTTP seam that sends all the app's traffic to a local server of the fixture's covers: `cmd/sona/e2e_probe.go`, `SONA_E2E=1`, `SONA_E2E_CDN`), starts it on the fixture profile with no network, and drives it through the automation socket (`e2e/automation`): first paint, Albums listing the fixture albums, a click on an album's play button, the player bar playing, Space pausing and resuming, a captured PNG, a clean quit on SIGTERM. A second test reads the shell's landmarks (application and window, sidebar link, history buttons, page region, album play buttons, the player's transport and sliders) from the AT-SPI bus by role and name (`e2e/atspi`, D-Bus only). `E2E_OUT=<dir>` keeps the capture and the app's stderr; `E2E_BIN` skips the build. The probe build never ships (`probe` and `mygo_noinspector` exclude each other).

### Catalogue pages (`features/album`, `features/artist`, `features/song`)

`/album/{id}` (`?song=<id>` marks and scrolls to a song), `/artist/{id}`, `/artist/{id}/view/{view}` and `/song/{id}`: v0.2.0's pages over the library or catalogue services (a library id reads `LibraryService`, a catalogue id `CatalogService`; a library album or artist with a catalogue id also loads the catalogue page for Apple's sections). Every page query is `store.Forever` (v0.2.0's default `staleTime`), keyed as v0.2.0's. Each page has its skeleton and `DetailError` with Retry; the album's layout follows the content width (320, 256 or 168 DIP cover) and its countdown re-reads every minute; `album.go-to`, `artist.go-to` and `song.view-credits` are the song rows' actions. Cross-page links render only where `Env.HasRoute` says the page exists (`kit.ArtistLinks` takes `ArtistLinksOpts{HasRoute}`).

- **Item state** (rating, add and remove with toasts, one batched `States` call a frame) is `kit.ItemStates` (`kit/song_itemstate.go`), the one layer for every page, list and the player's rating buttons: `app.New` and `uitest.New` build one `Env.ItemStates`, which follows `library:item-state` (`Remember`) and refreshes the library lists when an item joins or leaves the library. It offers `Load`, `Change` (optimistic `store.Set`, which cancels a fetch in flight), `Rate`, `Add`, `Remove` and the bulk `RateMany`, `AddMany`, `RemoveMany`, with the header's `LibraryButton` and `RatingButtons`.
- **The song page** is built by `frame`, which loaded and loading share: from 860 DIPs of content the cover, title, artists, album and actions sit in a `kit.Backdrop` spine (cover 240) beside the body (details ledger, credits grid, lyrics), narrower they are a band (cover 136) over it. The people to a row of a credit group (1 to 3) come from the room the column has (`shapeOf`), not from a measured width, so the page builds once.
- **Lyrics** are `store.UseLyrics` under `store.KeyLyrics(id)` (`["catalog","lyrics",id]`, always a `services.Lyrics`), the one cache the song page and Now Playing read.
- **Tracklist.** `TrackListState.BlockTop` and `ScrollToBlock` give the album's disc index its jump (work headings are measured from the last frame, so wrapped ones count). The album's sleeve contents use `Element.Sticky` (top 0) inside the full-height sleeve column, when the previous frame's height fits the pane; the page scroll has no padding of its own, so the sleeve is flush to the pane's edges and each part sets its gutters.
- **Formatting** of running times, the countdown and release dates is `i18n.FormatRunningTime`, `FormatTimeLeft` and `ShortReleaseDate`, on the regional format locale (`i18n.Locales()[0]`); a relative time is `i18n.RelativeTime` (freshness) or `i18n.RelativeDay` (calendar words), a playback time `i18n.FormatDuration` (m:ss) and a size `i18n.FormatBytes` ("12 kB"). No feature keeps its own copy of these.
- Collection play goes through `Env.Queue` (`kit.QueueCommands`): `PlaySongs`, `ShuffleSongs`, `PlayVideos`, `QueueItems` and `Replace`, which ask first or offer Undo before replacing a long queue; features call it on the main thread.
- Pure logic (compilation rule, writers, classical grouping, release counts, credit titles) has Go unit tests, and so has the cover-colour palette (`theme/palette`).
